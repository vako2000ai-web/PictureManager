# PictureManager

Локальное web-приложение для наведения порядка в архиве фото и видео: каталог в SQLite, поиск точных дублей
(SHA-256), раскладка файлов по датам съёмки (`ГГГГ/ММ/ДД`) и конвертация HEIC → JPEG.
Работает только на вашем ПК: сервер слушает `127.0.0.1`, из сети недоступен.

## Установка

Нужен Python 3.10+.

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows;  Linux/macOS: source .venv/bin/activate
pip install -e ".[dev]"
```

### ffmpeg / ffprobe (по желанию)

Нужны для даты съёмки видео (`ffprobe`) и миниатюр видео (`ffmpeg`). Установите их и добавьте в `PATH`
(Windows: `winget install Gyan.FFmpeg`) либо укажите пути в настройках (`ffprobe_path`, `ffmpeg_path`).
Без них приложение работает: дата видео берётся из имени файла или времени изменения, вместо миниатюры
показывается заглушка, а в интерфейсе выводится предупреждение.

## Запуск

```bash
python -m app                 # откроет http://127.0.0.1:8765/
python -m app --port 9000 --data-dir D:\pm-data --no-browser
```

База (`catalog.db`) и кэш миниатюр лежат в каталоге данных (`data/` или `PM_DATA_DIR`).
Каталог — это индекс: если удалить базу, повторный скан его восстановит (ручные правки дат при этом теряются).

## Порядок работы

1. **Источники** — добавьте диски/каталоги и запустите сканирование. Повторный скан обрабатывает только новые
   и изменённые файлы; исчезнувшие получают статус `missing`. Корень определяется по идентификатору тома,
   поэтому смена буквы диска не создаёт дублей (при повторном добавлении тот же диск распознаётся).
2. **Каталог** — лента по дням с фильтрами; дату можно задать вручную (она имеет наивысший приоритет).
   Дата определяется каскадом: EXIF / метаданные видео → имя файла → время изменения (низкая уверенность).
3. **Дубли** — точные копии (сначала по размеру, затем SHA-256). Оригинал предлагается автоматически
   (файл в структуре `ГГГГ/ММ/ДД`, затем короткий путь, затем ранний mtime) и меняется вручную.
   Лишние копии уходят в `_duplicates` внутри своего корня, а не удаляются; из карантина их можно восстановить.
4. **Перемещение** — постройте план (пути назначения, конфликты, объём, свободное место), проверьте и подтвердите.
5. **HEIC → JPEG** — JPEG кладётся рядом с оригиналом (EXIF, дата и ICC-профиль сохраняются, ориентация применяется
   к пикселям). Оригинал остаётся, пока вы явно не перенесёте его в карантин.
6. **Журнал** — все перемещения, карантин и конвертации.

## Меры безопасности при перемещении

- Ничего не двигается без явного подтверждения плана; перед подтверждением показывается сводка.
- Перемещение внутри одного диска — атомарное переименование. Между дисками: копия → сверка SHA-256 → только
  потом удаление оригинала; при расхождении копия удаляется, оригинал остаётся.
- Каждая операция пишется в журнал до и после выполнения. После аварийного завершения при следующем запуске
  прерванные операции доводятся до конца или отменяются без потери файлов.
- Файл, у которого размер или время изменения не совпадают с каталогом, пропускается и попадает в отчёт.
- Существующие файлы не перезаписываются: при другом содержимом добавляется суффикс `_1`, `_2`, при том же —
  файл уходит в карантин.
- Перемещённые файлы можно вернуть откатом плана (если на новом месте они не менялись).
- Связанные файлы (RAW+JPEG, Live Photo HEIC+MOV) всегда едут вместе, папку определяет основной файл.
- Пустые исходные папки автоматически не удаляются.

## Принятые решения (по открытым вопросам дизайна)

- Время видео: `creation_time` считается локальным временем, пояс отбрасывается; EXIF-время тоже локальное.
- `ffmpeg`/`ffprobe` устанавливает пользователь; без них приложение деградирует с предупреждением.
- Граница суток настраивается (`day_boundary_hour`, по умолчанию 0).
- Пустые исходные папки не удаляются.
- Корень назначения выбирается для каждого плана отдельно.
- Конвертация сейчас только HEIC → JPEG (`app/heic.py`); общий интерфейс конвертеров отложен до появления второго формата.
