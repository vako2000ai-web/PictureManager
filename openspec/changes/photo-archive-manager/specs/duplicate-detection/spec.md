## ADDED Requirements

### Requirement: Поиск точных дублей
Система SHALL находить точные дубли как файлы с одинаковым SHA-256 и объединять их в группы дублей.

#### Scenario: Два одинаковых файла
- **WHEN** два файла в разных каталогах имеют одинаковое содержимое
- **THEN** они образуют одну группу дублей

#### Scenario: Разное содержимое
- **WHEN** размеры или хеши файлов различаются
- **THEN** файлы не считаются дублями

### Requirement: Двухэтапное хеширование
Система SHALL сначала группировать файлы по размеру и вычислять SHA-256 только для файлов, размер которых совпадает с размером другого файла; хеш MUST вычисляться потоково, блоками, и кэшироваться по паре размер и время модификации.

#### Scenario: Уникальный размер
- **WHEN** размер файла не совпадает ни с одним другим файлом каталога
- **THEN** SHA-256 для него не вычисляется на этапе поиска дублей

#### Scenario: Использование кэша
- **WHEN** размер и время модификации файла не изменились с прошлого вычисления
- **THEN** сохранённый хеш используется без повторного чтения файла

### Requirement: Исключение производных и связанных файлов
Система SHALL NOT считать дублями файлы одной группы связанных файлов (RAW и JPEG, Live Photo) и файлы, созданные конвертацией, относительно их оригиналов.

#### Scenario: Live Photo
- **WHEN** HEIC и MOV образуют Live Photo
- **THEN** они не попадают в одну группу дублей

#### Scenario: Конвертированный JPEG
- **WHEN** JPEG получен конвертацией из HEIC
- **THEN** пара не предлагается как дубли

### Requirement: Выбор оригинала
Система SHALL предлагать оригинал в каждой группе дублей по правилу по умолчанию (файл в целевой структуре, затем самый короткий путь, затем самое раннее время модификации) и позволять пользователю выбрать оригинал вручную.

#### Scenario: Правило по умолчанию
- **WHEN** группа содержит файл в структуре `ГГГГ/ММ/ДД` и файл вне её
- **THEN** оригиналом предлагается файл в структуре

#### Scenario: Ручной выбор
- **WHEN** пользователь выбирает другой файл оригиналом
- **THEN** выбор сохраняется и применяется при обработке группы

### Requirement: Карантин для лишних копий
Система SHALL переносить лишние копии в карантин, а не удалять сразу, и записывать каждую операцию в журнал с возможностью восстановления.

#### Scenario: Перенос в карантин
- **WHEN** пользователь подтверждает обработку группы дублей
- **THEN** все файлы, кроме оригинала, переносятся в карантин, а записи каталога получают статус `quarantined`

#### Scenario: Восстановление
- **WHEN** пользователь восстанавливает файл из карантина
- **THEN** файл возвращается на прежний путь, если он свободен, а статус записи меняется на `present`
