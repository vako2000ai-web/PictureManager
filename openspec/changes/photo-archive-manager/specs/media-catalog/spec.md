## ADDED Requirements

### Requirement: Каталог в SQLite
Система SHALL хранить каталог медиафайлов в базе SQLite: путь, размер, время модификации, тип, статус, хеш SHA-256, дату съёмки и источник даты.

#### Scenario: Сохранение записи
- **WHEN** сканер обрабатывает новый файл
- **THEN** в каталоге создаётся запись с размером, временем модификации, типом и датой съёмки

#### Scenario: Пересоздание индекса
- **WHEN** файл базы данных удалён
- **THEN** повторное сканирование восстанавливает записи файлов, а ручные правки дат в этом случае утрачиваются

### Requirement: Определение даты съёмки
Система SHALL определять дату съёмки по каскаду источников: EXIF `DateTimeOriginal` для фото или метаданные контейнера для видео, затем дата в имени файла, затем время модификации файла.

#### Scenario: Дата из EXIF
- **WHEN** у фото есть EXIF `DateTimeOriginal`
- **THEN** дата съёмки берётся из EXIF, источник записывается как `exif`

#### Scenario: Дата из имени файла
- **WHEN** EXIF отсутствует, а имя файла имеет вид `IMG_20240715_101500.jpg`
- **THEN** дата съёмки берётся из имени, источник записывается как `filename`

#### Scenario: Дата из времени модификации
- **WHEN** EXIF и дата в имени отсутствуют
- **THEN** используется время модификации, источник записывается как `mtime` с пониженной уверенностью

#### Scenario: Дата неизвестна
- **WHEN** ни один источник не дал корректной даты
- **THEN** дата съёмки остаётся пустой, файл помечается как «без даты»

### Requirement: Ручная правка даты
Система SHALL позволять пользователю задавать дату съёмки вручную для файла или группы файлов; ручная дата MUST иметь наивысший приоритет и не затираться повторным сканированием.

#### Scenario: Правка даты
- **WHEN** пользователь задаёт дату для выбранных файлов
- **THEN** дата сохраняется с источником `manual` и используется при построении плана перемещения

#### Scenario: Повторное сканирование
- **WHEN** после ручной правки выполняется повторное сканирование
- **THEN** ручная дата сохраняется

### Requirement: Поддержка видео
Система SHALL включать в каталог видеофайлы и определять их дату съёмки по метаданным контейнера; при недоступности `ffprobe` система MUST продолжить работу, используя дату из имени файла или время модификации.

#### Scenario: Видео с метаданными
- **WHEN** доступен `ffprobe` и у видео есть `creation_time`
- **THEN** дата съёмки берётся из метаданных контейнера

#### Scenario: Нет ffprobe
- **WHEN** `ffprobe` не найден
- **THEN** дата видео определяется по имени файла или времени модификации, а в интерфейсе показывается предупреждение

### Requirement: Связанные файлы
Система SHALL связывать файлы одной съёмки (RAW и JPEG, HEIC и MOV Live Photo) по имени без расширения в одном каталоге и присваивать им общий ключ группы.

#### Scenario: Пара RAW и JPEG
- **WHEN** в одном каталоге лежат `IMG_0001.CR2` и `IMG_0001.JPG`
- **THEN** файлы получают общий ключ группы, а дата берётся у основного (фото) файла

### Requirement: Просмотр и сортировка каталога
Система SHALL предоставлять просмотр каталога с сортировкой и группировкой по дате съёмки, фильтрацией по типу файла, корню и статусу.

#### Scenario: Группировка по дням
- **WHEN** пользователь открывает ленту каталога
- **THEN** файлы показываются сгруппированными по дням, с сортировкой от новых к старым или наоборот
